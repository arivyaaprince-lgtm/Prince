# Monarch AI App

Monarch is a standalone mobile-friendly app workspace in `app/`, separate from Princess AI and not dependent on Floot.

## Features in this version
- Local starter templates, AI-generated single-file HTML apps, HTML editing, sandboxed live preview, browser-local save/restore, HTML download, and project JSON export.
- Monarch AI chat connected to `POST /api/chat`, with account-scoped PostgreSQL conversation storage and a `GET /api/chat/history/latest` restore endpoint.
- Email/password signup, login, session check, and logout using the existing PostgreSQL-backed auth starter.
- OpenAI-compatible chat-completions provider support (the example defaults to OpenRouter).
- Input validation, bounded conversation size, a 45-second upstream timeout, sanitized provider errors, and rate limiting.
- Provider keys stay on the server; never put a real API key in frontend code or commit one to GitHub.

## Deployment path (no Floot)
1. Create a free PostgreSQL database with a provider such as Neon. Copy its connection string; do not share it in chat or commit it.
2. Create an API key with your chosen model provider. For the example OpenRouter provider, use a model available to your account; the default `openrouter/free` may have changing availability and limits.
3. Open the Render dashboard and choose **New → Blueprint**, then connect the GitHub repository `arivyaaprince-lgtm/Prince`. Render reads `render.yaml`.
4. When asked for `DATABASE_URL`, paste the database connection string into Render's secret/environment form. For `AI_API_KEY`, paste the provider key there. Do not add either secret to GitHub or to the app's backend URL field.
5. Wait for Render to build and deploy, then open the Render service URL. The frontend and API are served from the same origin so account cookies can work without cross-site setup. On first open, create an account and start chatting.

The blueprint uses Render's free web-service plan where available; free services can sleep when idle and are not a 24/7 uptime guarantee. Provider free-tier availability, quotas, and database limits can change. Review all provider usage limits before public launch.

## Environment variables
- `DATABASE_URL`: PostgreSQL connection string.
- `SESSION_TOKEN_PEPPER`: generated by Render in the blueprint.
- `AI_API_KEY`: provider secret.
- `AI_BASE_URL`: default `https://openrouter.ai/api/v1`.
- `AI_MODEL`: default `openrouter/free`; choose a supported model if needed.
- `APP_ORIGINS`: optional comma-separated browser origins. Same-host requests are allowed automatically; the GitHub Pages origin can be added if using Pages as a separate frontend.

## Architecture and limits
GitHub Pages can host only the static frontend; it cannot run Express or protect provider secrets. The Render blueprint serves the frontend and API together. The existing Express server initializes PostgreSQL and validates `SESSION_TOKEN_PEPPER` at startup. AI chat requires a signed-in account and is rate-limited, but add account-level quotas and provider spend monitoring before a public launch.

The source code is committed and the backend TypeScript build has passed CI. AI generation still needs a successful hosting deployment plus provider/database credentials entered through their hosting dashboards; no live AI service is claimed until that is verified.
